## 三、需求方案

### 功能 1：钟点 · 半日租档期（P0）

#### 背景与痛点
现仅支持整栋按天租。大量轰趴只是"周六下午到晚上玩一场"，按天计费门槛太高，劝退性价比型用户（同学会/闺蜜趴）。途家美团都按天，这正是轰趴垂直场景该破的局。

#### 目标用户
聚会发起人、生日策划人（短时段、性价比敏感）。

#### 功能描述
别墅支持按"时段档"售卖：整天 / 半日（如 12:00–22:00）/ 钟点（如 4 小时）。用户预订时先选档期再选日期，房态按时段锁定，一天内非冲突时段可接多场。

#### 用户故事
- 作为聚会发起人，我想要只租一个下午，以便不用为整天买单。
- 作为商家，我想要一天接午/晚两场，以便提高翻台率和坪效。

#### 核心交互流程
1. 商家在房源后台为别墅配置可售档期（类型/时间窗/价格/平日周末节假日定价）
2. C 端详情页展示档期选项，用户先选档期 → 选日期 → 看该档期该日是否可订
3. 提交订单，房态按"日期 + 档期时间窗"锁定（Redis 锁 key 含时间窗）
4. 同一天不同档期若时间不冲突，可分别被预订

#### 关键规则
- 整天档与任意半日/钟点档在同一天互斥（整天锁则当天不可再售时段）
- 半日/钟点档之间，时间窗不重叠才能共存
- 押金、折扣按档期规则重算（连住折扣仅对整天档生效）
- 兼容存量：未配置档期的别墅默认仅整天档，行为不变

#### 数据需求
- 新增 `villa_time_slot`（villaId、type、startTime、endTime、price、weekendPrice、holidayPrice、status、sortOrder）
- `order` 增加 `slotId` / `slotType` / `slotStart` / `slotEnd` 字段
- `villa_calendar` 锁粒度从"按天"扩展为"按天+时间窗"（新增可订时段占用记录或在锁层处理）

#### 优先级与排期建议
- 优先级：P0　预估：后端 3 天 + 前端 2 天 + 后台 1 天
- 风险：房态锁冲突逻辑是核心难点，需先设计锁粒度再编码

#### 成功指标
- 钟点/半日订单占比 ≥ 25%
- 单别墅日均成交场次提升（翻台率）

### 功能 2：实时管家 IM（P1）

#### 背景与痛点
入住期间"投影怎么连""空调不制冷""加订烧烤"找不到人，是轰趴差评重灾区。现有 message 表只是通知型，非双向会话。

#### 目标用户
入住中的所有用户 + 商家客服。

#### 功能描述
订单维度的商家↔客人实时会话，入住期间在订单详情置顶；支持图片、商家 FAQ 快捷回复。

#### 用户故事
- 作为入住客人，我想要随时找到管家，以便设施出问题能马上解决。
- 作为商家，我想要集中处理客人消息，以便不漏接、可沉淀常见问答。

#### 核心交互流程
1. 用户在订单详情点"联系管家"进入会话
2. 双向发文字/图片，未读数提醒
3. 商家后台有会话工作台，可设置 FAQ 快捷回复
4. 入住期内会话在订单页置顶高亮

#### 关键规则
- 会话绑定订单，仅订单双方 + 该商家管理员可见
- 消息持久化，离线消息通过 user_message/admin_message 通知补达

#### 数据需求
- 新增 `service_chat`（orderId、merchantId、userId、lastMessageAt、unread 计数）
- 新增 `service_chat_message`（chatId、senderType user/merchant、senderId、type text/image、content、readAt）

#### 优先级与排期建议
- 优先级：P1　预估：后端 2 天 + 小程序 2 天 + 后台 2 天

#### 成功指标
- 入住期消息响应率、差评率下降

### 功能 3：会员复购体系 + 复购提醒（P1）

#### 背景与痛点
轰趴是强周期复购场景（每年生日、季度团建、节日聚会），但下单后关系即断。V1 不做优惠券，但会员≠优惠券。

#### 功能描述
成长值/等级 + 复购权益（生日免押、老客优先房态）+ 基于历史订单的复购智能提醒。

#### 用户故事
- 作为老客，我想要有会员权益，以便复购更划算、被记住。
- 作为平台，我想要在用户复购周期临近时提醒，以便唤回。

#### 数据需求
- `user` 增加成长值/等级字段或新增 `user_membership`
- 新增 `growth_log`（来源订单/评价等加分流水）
- 复购提醒：基于 order.createdAt + 场景，定时任务生成 user_message

#### 优先级与排期建议
- 优先级：P1　第二批

---

### 功能 4：入住人登记 + 派对公约（P1，轻量）

#### 背景与痛点
轰趴扰民/安全事故是行业高危点，平台有连带责任。现在下单不收集到场信息、不告知噪音规则。

#### 功能描述
下单/入住前电子签"派对公约"（噪音时段、人数上限、损坏责任），可选登记带队人实名。

#### 数据需求
- `order` 增加 `pactSignedAt`（公约签署时间）
- 可选新增 `order_guest`（带队人姓名/手机/身份证后四位）
- 派对公约文本走 site_config 商家可配

#### 优先级与排期建议
- 优先级：P1　开发量小，可顺手做
