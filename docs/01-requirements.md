# 别墅轰趴预订小程序 — 需求文档

## 需求摘要

### 目标

打造一个微信小程序，让用户可以按日期、人数、设施筛选别墅场地，支持套餐加购和在线支付，完成轰趴/团建/生日聚会的一站式预订。后台提供房源、房态、价格、订单的完整管理能力。

### 成功标准

- [ ] 用户可以按日期、人数、设施条件搜索可用别墅
- [ ] 用户可以查看别墅详情（图片、设施、价格、评价）
- [ ] 用户可以选择日期并提交预订
- [ ] 用户可以加购套餐（烧烤、KTV、桌游、生日布置等）
- [ ] 用户可以通过微信支付完成付款
- [ ] 用户可以查看、取消、管理自己的订单
- [ ] 管理员可以管理房源信息（新增/编辑/上下架）
- [ ] 管理员可以管理房态日历（可订/不可订/价格调整）
- [ ] 管理员可以查看和处理订单（确认/拒绝/退款）
- [ ] 管理员可以管理套餐和加购项

### 非目标

- 不做 APP（只做微信小程序）
- 不做多租户（单商家模式）
- 不做即时通讯/在线客服（可接入微信客服）
- 不做房东入驻（平台自营模式）
- V1 不做优惠券/营销活动系统

### 约束

- 平台：微信小程序（需遵循微信审核规范）
- 支付：微信支付（需商户号）
- 【假设】单次预订最少 1 天，按天计费
- 【假设】同一别墅同一天只能被一组客人预订（整栋出租）
- 【假设】预订需要提前至少 1 天

### 用户角色

| 角色 | 说明 |
|------|------|
| 游客 | 可浏览别墅，不可下单 |
| 用户 | 微信授权登录后，可预订、支付、评价 |
| 管理员 | Web 后台登录，管理房源/订单/套餐 |

### 核心业务流程

```
用户浏览别墅 → 选择日期 → 筛选确认 → 选择套餐 → 查看连续折扣
  → 提交订单（含押金） → 微信支付（订单金额 + 押金）
  → 支付成功 → 等待确认
  → 管理员确认 → 入住 → 退房 → 管理员验收押金
  → 退还押金 → 评价 → 已完成
```

```
订单状态流转：
待支付 → 已支付/待确认 → 已确认/待入住 → 已入住 → 待退押金 → 已完成
  ↘ 已取消（用户取消）       ↘ 已拒绝（管理员拒绝，触发全额退款含押金）
  ↘ 超时关闭（30分钟未支付）
```

### 假设与待确认

- 【假设】按天计费，入住时间为当天 14:00，退房时间为次日 12:00
- 【假设】整栋出租，不支持分房间预订
- 【假设】支付后不自动确认，需管理员审核
- 【假设】取消政策：入住前 3 天免费取消，3 天内取消收取 50% 费用
- 【已确认】需要押金，退房后无损坏则退还
- 【已确认】多天连续预订支持折扣
- 【已确认】套餐区分日期定价（如周末套餐价格不同）
- 【已确认】不校验预订人数上限

### 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 微信支付商户号审核周期 | 阻塞支付功能上线 | 提前申请，开发期用沙箱 |
| 并发预订同一日期 | 超售 | 库存锁定 + 乐观锁 |
| 小程序审核被拒 | 延迟上线 | 提前了解类目要求，准备资质 |
