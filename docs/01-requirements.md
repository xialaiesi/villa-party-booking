# 别墅轰趴预订 SaaS 平台 — 需求文档

## 需求摘要

### 目标

打造一个多租户的别墅轰趴预订 SaaS 平台。C 端为微信小程序，让用户可以按日期、人数、设施筛选全平台所有商家的别墅场地，支持套餐加购、在线支付、活动方案、拼团裂变等全场景玩法。B 端支持多商家入驻，每个商家独立管理自己的房源、订单、套餐，平台自动分账。

### 核心卖点

相比通用短租平台（途家、美团民宿），本平台主打**轰趴垂直场景**，做别人没做深的差异化：
- 不只订房，还帮你玩（活动方案、氛围包、周边服务）
- 不只个人，还服务企业（老板买单、团建方案 PDF）
- 不只交易，还有社区（趴友圈、趴后回忆、拼团裂变）

### 非目标

- 不做 APP（只做微信小程序 + Web 管理后台）
- V1 不做优惠券/营销活动系统
- V1 不做商家入驻审核流程（直接开通）

### 约束

- 平台：微信小程序（需遵循微信审核规范）
- 支付：微信支付（需商户号）
- 【假设】单次预订最少 1 天，按天计费
- 【假设】同一别墅同一天只能被一组客人预订（整栋出租）
- 【假设】预订需要提前至少 1 天

### 用户角色

| 角色 | 说明 | 访问范围 |
|------|------|----------|
| 游客 | 未登录 | 仅浏览别墅和内容 |
| 用户 | 微信授权登录后 | 全平台别墅浏览、下单、支付、评价、社区 |
| 商家 | Web 后台登录 | 管理自己的房源/订单/套餐/财务 |
| 平台超管 | Web 后台登录 | 管理所有商家、全平台数据、结算 |

### 核心业务流程

```
用户浏览全平台别墅 → 选择日期 → 筛选确认 → 选择套餐/氛围包/方案
  → 提交订单（含押金） → 微信支付（订单金额 + 押金）
  → 支付成功 → 等待商家确认
  → 商家确认 → 【系统自动创建分账记录】 → 入住
  → 退房 → 商家验收押金 → 退还押金 → 评价 → 已完成
  → 平台超管标记结算完成 → 商家收到款项
```

```
订单状态流转：
待支付 → 已支付/待确认 → 已确认/待入住 → 已入住 → 待退押金 → 已完成
  ↘ 已取消（用户取消）       ↘ 已拒绝（商家拒绝，触发全额退款含押金）
  ↘ 超时关闭（30分钟未支付）
```

### 已确认的业务规则

- 【已确认】SaaS 多租户模式，商家直接开通不需要审核
- 【已确认】平台自动分账到商家，V1 平台免佣金（佣金率 0）
- 【已确认】复用同一套管理后台，根据角色显示不同菜单
- 【已确认】需要押金，退房后无损坏则退还
- 【已确认】多天连续预订支持折扣（3/5/7 天阶梯）
- 【已确认】套餐区分日期定价（平日/周末/节假日）
- 【已确认】不校验预订人数上限
- 【已确认】入住时间 14:00，退房时间次日 12:00
- 【已确认】取消政策：入住前 3 天免费，3 天内收 50%

### 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 微信支付商户号审核周期 | 阻塞支付功能上线 | 提前申请，开发期用沙箱 |
| 并发预订同一日期 | 超售 | Redis 分布式锁 + 数据库乐观锁 |
| 小程序审核被拒 | 延迟上线 | 提前了解类目要求 |
| 多商家数据隔离漏洞 | 数据泄漏 | 所有 admin service 强制 merchantId 过滤 + ensureAccess 检查 |
